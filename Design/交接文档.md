# Choke! 交接文档

> 更新时间：2026-11-16
> 交接基线：`master` 本地提交 `c58cd86` + 当前工作区未提交改动
> 适用对象：接手开发、构建、测试或部署的人

## 1. 项目是什么

Choke! 是一个把 osu! 玩家数据做成卡牌的单机收藏 + 实时战斗游戏：

- 用 osu! 账号登录，开包抽卡，在卡册收藏、培养卡牌；
- 在牌桌上编队，进入边线战场进行单人 PvE；
- Windows 客户端 `Choke.exe` 用 WebView2 承载 React 界面，本机同时启动 Fastify API 和静态页面服务；
- 数据存在本机 PGlite（嵌入式 PostgreSQL）里，不依赖外部数据库。

当前没有线上服务、账号后端或多人联机；所有存档都在本机。

## 2. 当前完成度

已经可玩的闭环：

- **账号**：osu! OAuth 登录、首次登录建号、`CHOKE ID #xxxxxx`、新手礼包、退出登录。
- **牌桌**：发卡包、开包、撕包/翻卡演出、桌面拖拽、抽屉收纳、卡册/卡组/背包/市场/关于书本。
- **收藏**：卡册筛选、排序、分页、卡牌详情、闪卡外观、分解与精华镀闪。
- **抽卡**：六档卡池、服务端 RNG、60 抽保底、卡包 token、闪卡独立概率。
- **市场**：金币上架、下架、购买，`user_card` 所有权转移。
- **培养**：等级、阶数（命座）、训练点进阶、经验、Mod、称号、四职业 V2 规则。
- **战斗**：战斗大厅 → 边线试战 → 选卡 → 战备 → 实时 PvE；服务端签发快照、固定步长重放、幂等结算。
- **技能**：约 1470 项技能资产，含独立演出、预览、分镜和逐项验证记录。
- **客户端**：启动画面、登录跳转、F11 全屏、Esc 返回、F10 开发者工作台、F12 检查器（开发模式）。

战斗规则存在两套并存版本：

- `legacy-v1`：旧的 14 来源/子职业规则，保留给旧存档和经典模式；不要在没有迁移方案时删除。
- `four-v2`：战斗 / 坦克 / 法师 / 辅助四职业，新账号默认使用。

## 3. 快速启动

### 3.1 玩家方式

1. 确认已安装 **WebView2 Runtime**（Windows 10/11 通常自带）。
2. 在仓库根目录双击 `Choke.exe`。
3. 首次启动会拉起本机 API（3100）和页面服务（5173），随后显示牌桌。
4. 正式存档默认在 `apps/api/.data/pg`。

仓库不跟踪 `Choke.exe`。新克隆后需要先构建：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-desktop.ps1
```

改动 `apps/desktop/*.cs` 或图标后，加 `-RebuildExecutable` 重新编译 EXE：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-desktop.ps1 -RebuildExecutable
```

脚本会下载 WebView2 SDK 到 `.cache/desktop`、编译 C# 客户端，并执行 Vite 构建。如果当前 EXE 已签名，脚本会用同一张证书签新版，验证通过后才替换。

### 3.2 开发方式

```powershell
.\Choke.exe --developer
```

开发模式默认打开 `http://127.0.0.1:5273`，API 在 `3320`，存档在 `.cache/developer/<profile>`（默认 `pg`），不会碰正式存档。

- F10 / 「关于 → 开发者工具」：资源补充、卡牌编辑器、卡面实验室、卡池实验室。
- F12：WebView2 检查器。
- 使用其它测试档：设置环境变量 `CHOKE_DESKTOP_TEST_PROFILE`，只允许小写字母、数字和连字符。

不经过 EXE、直接跑本机服务：

```powershell
cd apps/api
node --import tsx src/desktop.ts developer
```

它等价于同时启动 API + Vite 开发服务器。也可以分开跑：

```powershell
# API（默认 3100）
node --import tsx src/index.ts

# 前端开发服务器（默认 5173，代理 /api 和 /auth 到 3100）
node ..\..\node_modules\vite\bin\vite.js
```

> 根 `package.json` 当前不再提供 `dev` / `dev:api` 脚本，桌面客户端是推荐入口。若恢复脚本，注意不要和 `desktop.ts` 的端口/锁冲突。

### 3.3 端口与模式对照

| 模式 | 前端 | API | 存档目录 | 登录 |
|---|---|---|---|---|
| 正式（双击 EXE） | `http://localhost:5173` | `http://localhost:3100` | `apps/api/.data/pg` | osu! OAuth |
| 开发（`--developer`） | `http://127.0.0.1:5273` | `http://127.0.0.1:3320` | `.cache/developer/<profile>` | 本机测试号 |
| 测试入口（桌面「测试号登录」） | `http://127.0.0.1:5273` | `http://127.0.0.1:3320` | `.cache/developer/<profile>` | 本机测试号 |

**不要混用 `localhost` 和 `127.0.0.1`**：cookie 不共享，登录状态会丢。

## 4. 环境配置

在仓库根目录复制 `.env.example` 为 `.env`。API 会从 `apps/api` 的工作目录向上查找，根目录这份会被读到。`.env` 已 gitignore，不要加 `VITE_` 前缀。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `OSU_CLIENT_ID` | 无 | osu! OAuth Client ID；示例配置使用 `74418` |
| `OSU_CLIENT_SECRET` | 无 | osu! OAuth Client Secret，不要提交 |
| `SESSION_SECRET` | 回退到 client secret | session cookie 签名；建议显式配置长随机串 |
| `API_BASE_URL` | `http://localhost:3100` | OAuth 回调 base，末尾不要带斜杠 |
| `WEB_BASE_URL` | `http://localhost:5173` | 登录成功后跳回的前端地址 |
| `PG_DATA_DIR` | `./.data/pg` | 相对 `apps/api` 工作目录解析 |
| `PORT` | `3100` | API 端口；改它要同步改 `API_BASE_URL` 和 Vite 代理 |

osu! 应用设置里的 **Callback URL 必须精确为**：

```text
http://localhost:3100/auth/osu/callback
```

不能留空、不能带结尾斜杠、不能写 `127.0.0.1`、端口必须是 3100。

测试模式会自己生成随机 `SESSION_SECRET`，并绕过 OAuth，不需要配置 osu! 应用。

## 6. 核心系统说明

### 6.1 卡牌与收藏

- `cards` 是静态卡牌定义，来自 osu! 玩家数据；`user_cards` 是玩家持有的实例。
- 实例带等级、阶数、经验、闪卡外观、Mod；新抽到的卡固定从 Lv.1 / 0 阶开始。
- 卡面绘制集中在 `src/card/CardFace.tsx`，卡册、牌桌、战斗共用。
- 分解重复卡获得精华，闪卡 3 倍；精华只用于镀闪，经验来自熔卡。

### 6.2 抽卡

- 六档卡池定义在 `apps/api/src/gacha/pools.ts`，权重和 RNG 都在服务端。
- 60 抽保底，进度存 `pity`；开包结果存 `pack_openings`。
- 从背包发到桌面会预扣卡包并生成一次性 `pack_tokens`；桌面卡包拖回背包会恢复库存。
- 卡池缺对应稀有度时开包会报“卡池里没有 X 档的卡”，先导入示例卡或全量卡池。

### 6.3 市场与货币

- 金币用于市场交易；精华用于镀闪。
- 上架、下架、购买都在 `apps/api/src/routes/market.ts`；购买后所有权直接转给买家。
- 同一张 `user_card` 同时只能有一个 active 挂单（数据库唯一索引保证）。

### 6.4 战斗

- 客户端运行 60 Hz 固定步长模拟，输入是移动、普攻、技能、回场等指令。
- 服务端在 `POST /users/:id/cultivation/start` 签发 UUID、随机种子和权威卡组快照；结算时重放操作，校验顺序、归属、胜负、用时、版本和技能条件。
- 每账号只保留一个有效进行中场次；重复结算返回旧结果，不重复发奖励。
- 正式 PvE 敌人按未培养的一级同卡组参考值固定，培养不会同步强化敌人。
- AI 在 `src/battle/edgeSkills/ai*.ts`，只做机制可用性判断和战术选择。

### 6.5 培养

- 核心在 `src/card/cultivation.ts`、`progression.ts`、`jobs.ts`、`combatRules.ts`。
- 等级、阶数、训练点、称号、10 件 Mod 已接入战斗和结算。
- 称号四选一，作用于全队；Mod 每账号每种一件、每卡两槽，可拆装和转移。
- 规则版本由 `cultivation_profiles.state.combatVersion` 保存；旧档案缺字段按 V1 解释。

详细数值和验收证据见 [培养系统 v1 实施与验收](培养系统%20v1%20实施与验收.md)。

### 6.6 桌面客户端

- `Choke.exe` 启动 `node --import tsx src/desktop.ts <mode>`，通过 stdin 管道生命周期绑定子进程：窗口关闭，API/页面服务一起退出。
- 正式模式需要 `dist/index.html`（由构建脚本生成）；开发模式直接起 Vite dev server。
- 客户端只允许本机 HTTP 页面、osu! 登录域名和本机 3100 的 `/auth/` 跳转；其它链接交给系统浏览器。
- 测试号入口是页面跳转到 `127.0.0.1:5273` 时自动启动测试 API。

## 7. 数据与存档

### 7.1 PGlite

- **单进程单连接**：API 运行时不要用另一个进程打开同一个数据目录；导入卡池前先退出游戏。
- 正式存档：`apps/api/.data/pg`
- 测试/开发存档：`.cache/developer/<profile>`（默认 `pg`），QA 脚本会使用随机新目录。
- 备份：完全退出游戏后，直接复制整个数据目录。

数据库表：

`cards`、`users`、`user_cards`、`decks`、`deck_slots`、`user_packs`、`pack_tokens`、`pack_openings`、`pity`、`market_listings`、`cultivation_profiles`、`combat_rule_releases`、`cultivation_runs`。

建表和增量迁移在 `apps/api/src/db/client.ts`，只做 additive 变更，不会批量重写旧卡。

### 7.2 全量卡池

仓库只跟踪 7 张示例卡。全量数据被 gitignore：

- `data/rankings.json`：排行榜同步产物（约 147 MB）
- `apps/api/data/choke-cards.json`：构建产物（约 90 MB）

流程：

```powershell
# 1. 同步排行榜（可复用已有文件）
pnpm sync:rankings -- --min-pp 2000 --active

# 2. 生成卡池
pnpm build:cards

# 3. 退出游戏后导入；--replace 只清空 cards 表
pnpm import:cards

# 只要示例卡
pnpm import:sample
```

`--replace` 不会删除 `user_cards`；如果卡定义变化太大，先备份数据目录。

## 8. API 一览

前端通过 Vite 代理访问 `/api/*`，代理会去掉 `/api` 前缀；直接请求 API 时不带前缀。

| 模块 | 主要路由 |
|---|---|
| 健康检查 | `GET /health` |
| 登录 | `GET /auth/osu`、`GET /auth/osu/callback`、`GET /auth/me`、`POST /auth/onboard`、`POST /auth/logout` |
| 卡牌 | `GET /cards`、`GET /cards/stats`、`GET /cards/countries`、`GET /cards/:id`、`GET /users/:id/cards`、`GET /users/:id/codex`、`GET /users/:id/codex/stats` |
| 卡包 | `GET /packs`、`GET /users/:id/packs`、`POST /users/:id/packs/:pool/take`、`POST /users/:id/packs/return`、`POST /users/:id/packs/mystery/open`、`POST /packs/:pool/open` |
| 卡组 | `GET /users/:id/deck`、`PUT /users/:id/deck` |
| 市场 | `GET /market/listings`、`GET /market/search`、`GET /users/:id/market/listings`、`POST /users/:id/market/list`、`DELETE /users/:id/market/listings/:listingId`、`POST /users/:id/market/buy/:listingId` |
| 养成 | `GET /users/:id/cards/:userCardId/fuel`、`POST .../level`、`POST .../constellation`、`POST .../melt`、`POST .../enhance` |
| 战斗/培养 | `GET/POST /users/:id/cultivation`、`POST /users/:id/cultivation/start`、`POST /users/:id/cultivation/settle` |
| 测试专用 | `GET /developer/state`、`POST /developer/fixtures`（仅 playtest API） |

除公开卡牌/市场查询外，`/users/:userId/...` 都要求 session：未登录 401，越权 403。

## 10. 已知边界与坑

1. **PGlite 单进程**：同时开游戏和导入脚本会失败或锁库；先退出，再导入。
2. **OAuth 端口固定**：回调必须是 `localhost:3100`；改端口要同步 osu! 应用、`API_BASE_URL` 和 Vite 代理。
3. **cookie 主机名**：`localhost` 与 `127.0.0.1` 不共享登录状态。
4. **全量卡池不在仓库**：新克隆只有 7 张示例卡，稀有池可能为空。
5. **两条战斗规则并存**：V1 是兼容基线，不要在没有迁移和回滚方案时删除。
6. **构建包体较大**：`BattlePage` 和战斗资源超过 500 kB 警告是已知现象，不影响运行。
7. **未验证生产 OAuth / 真实库升级 / 长时组合平衡**：正式部署前要单独做迁移演练。
8. **git 历史**：远端 `master` 是压缩后的单提交，本地 `Choke` 历史与它无共同祖先；不要直接 `git pull`/`merge`，按 PR 分支方式同步（见下）。

## 11. 交接时的 git 状态

交接时本地工作区包含大量未提交改动（战斗、培养、桌面客户端、设计文档），且本地历史与远端是两条独立历史。推荐做法：

- 以远端 `master` 为基线新建分支；
- 把当前工作区作为一次快照提交到该分支；
- 通过 fork + PR 提交，不直接改写 `master`；
- 合并前在干净克隆里执行 `pnpm install`、`pnpm typecheck`、`pnpm build`，并至少跑一遍 `check-cultivation` / `check-four-jobs`。

## 12. 后续建议

按优先级：

1. **CI**：把 `typecheck`、`build` 和核心 QA 脚本接入 GitHub Actions。
2. **自动化冒烟**：桌面启动、测试号登录、开包、进战斗、结算落库。
3. **前端拆包**：战斗页和技能演出按路由/技能懒加载，降低首包体积。
4. **生产数据库**：PGlite → PostgreSQL 16，补迁移脚本、连接池和多实例支持。
5. **安全与运维**：session 密钥管理、接口限流、市场异常交易校验、日志与备份策略。
6. **数据管线**：给 `rankings.json` 加快照版本/校验和，保证卡池可复现。
7. **内容与平衡**：继续用真人体验调整技能手感、难度和长时组合。
